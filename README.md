# DevTools Hub

DevTools Hub 是一个剪贴板历史管理器，支持 macOS 和 Windows，用 Rust + egui 编写，功能和实现思路参考 PasteNow。

另外参照 uTools 实现了鼠标中键快捷面板：在任意应用中选中 JSON 后按鼠标中键，可以直接用内置的 JSON 编辑器格式化。

PasteNow 的实现分析和证据见 [docs/PasteNow实现分析.md](docs/PasteNow实现分析.md)，uTools 鼠标中键面板的实现分析和证据见 [docs/uTools鼠标中键面板实现分析.md](docs/uTools鼠标中键面板实现分析.md)。

## 功能

- **后台记录**：轮询系统剪贴板的变化序号（macOS 的 `changeCount`、Windows 的 `GetClipboardSequenceNumber`），间隔可选 0.1 / 0.25 / 0.5 / 1 秒；保存剪贴板里的所有格式（纯文本、RTF、HTML、图片、文件……），粘贴时原样写回，格式不丢
- **去重**：对内容计算指纹，同一内容再次复制时只更新时间和复制次数
- **隐私规则**：默认忽略密码管理器标记为“不要记录”的内容（macOS 的 Concealed / Transient / AutoGenerated；Windows 的 `ExcludeClipboardContentFromMonitorProcessing`、`CanIncludeInClipboardHistory = 0` 等）；可以按应用排除，默认排除常见的密码管理器；可以忽略超大内容和空白文本
- **浮动面板**：界面参照 PasteNow，是一个窄长面板。条目以卡片显示：左侧是来源应用图标，中间是内容（文本、图片缩略图、文件、链接），右上角是时间，右下角是快速粘贴快捷键；底部显示条目总数。支持搜索和分类（全部 / 文本 / 链接 / 图片 / 文件 / 列表），按空格可以打开大预览。界面图标都是矢量绘制的；字体与系统界面一致，并自动校正中西文混排的基线
- **唤出方式**：点击菜单栏 / 托盘图标，面板贴着图标弹出；用全局快捷键唤出时，出现在鼠标附近、屏幕中央或上次的位置（可设置）
- **粘贴**：选中条目后写回剪贴板，把焦点还给之前的应用，再自动发送粘贴快捷键；也可以以纯文本粘贴，或者只复制
- **列表**：内置“收藏”，也可以自建列表；列表里的条目不会被自动清理
- **历史清理**：按保留时长（1 天到 1 年，或永久）和最大条数自动清理
- **菜单栏 / 托盘图标**：左键弹出 / 收起面板，右键打开菜单（暂停记录、设置、打开数据目录、退出）；不显示 Dock 图标或任务栏按钮
- **开机启动**：macOS 通过 LaunchAgent，Windows 通过注册表 `Run` 项
- **检查与安装更新**：启动时和之后每天查询一次 GitHub Releases 上最新的正式版本，有新版本时在面板顶部和菜单栏 / 托盘菜单中提示；点击“更新”在应用内下载、校验并替换旧版本，完成后自动重新启动。设置页底部可以手动检查，也可以跳过某个版本或关闭自动检查（见下文“检查更新与发布”）
- **鼠标中键快捷面板**（参照 uTools）：在其他应用中按鼠标中键，在鼠标处弹出面板。选中了文字时，模拟一次复制读出选中的内容（读完把剪贴板恢复原样，也不会记进历史），标题显示“选中的文本 N 个”，下面列出能处理它的功能；没有选中时列出常用功能。中键点击本身会被拦截，不再传给前台应用；可以在设置中关闭
- **JSON 编辑器**：选中 JSON（或在访达 / 资源管理器中选中一个 `.json` 文件）后从中键面板打开，自动格式化。数字的写法（`2.0`、超长整数）、键的顺序和注释都原样保留；转义过的 JSON（`{\"a\":1}`）会先去掉转义。带行号与语法高亮，格式错误时显示行列号并标出出错行，点击跳过去。支持重新格式化、去除注释、去除转义、复制、压缩复制、转义复制，缩进可选 2 / 4 / Tab，以及路径过滤（`.key.subkey`、`[0][1]`、`[-1]`、`.list[].name`）

### 两个平台的差异

| | macOS | Windows |
| --- | --- | --- |
| 默认唤起快捷键 | `⇧⌘V`（与 PasteNow 一致） | `Alt+Shift+V`（`Win+V` 是系统剪贴板历史，`Ctrl+Shift+V` 常被用作“粘贴为纯文本”） |
| 托盘图标 | 菜单栏，面板出现在图标正下方 | 通知区域，任务栏在下方时面板出现在图标上方 |
| 面板背景 | 原生毛玻璃 `NSVisualEffectView` | 不透明背景；Windows 11 上由系统绘制圆角 |
| 字体 | SF Pro + 苹方，等宽 SF Mono | Segoe UI + 微软雅黑 UI，等宽 Cascadia Mono / Consolas |
| 快捷键写法 | ⌘ ⇧ ↩ 等符号 | Ctrl、Shift、Enter 等文字 |
| 自动粘贴 | 需要“辅助功能”权限 | 不需要额外权限 |
| 鼠标中键监听 | `CGEventTap`，需要“辅助功能”权限 | 低级鼠标钩子 `WH_MOUSE_LL` |
| 读取选中内容 | 模拟 ⌘C | 模拟 Ctrl+C；控制台程序用 Ctrl+Insert，避免中断正在运行的命令 |
| 来源应用标识 | Bundle ID | 程序路径（排除规则可以只写文件名，如 `KeePass.exe`） |
| 数据目录 | `~/Library/Application Support/DevToolsHub/` | `%LOCALAPPDATA%\DevToolsHub\` |

## 鼠标中键快捷面板与 JSON 编辑器

快捷面板中：`↑` `↓` 选择，`↩` 或数字键 `1`–`9` 执行，`esc` 或点击别处关闭。

JSON 编辑器中（快捷键与 uTools 的 JSON 编辑器插件一致）：

| 按键 | 作用 |
| --- | --- |
| `⌥F` / `Alt+F` | 重新格式化 |
| `⌥C` / `Alt+C` | 压缩成一行并复制 |
| `⌥\` / `Alt+\` | 压缩、转义后复制 |
| `esc` | 关闭（回到之前的应用） |

编辑器左上角的 📌 可以固定窗口。uTools 本身也能用中键唤出面板，两者同时开启时，后启动的那个会先收到中键；请在其中一个里关掉（uTools：设置 › 超级面板，关闭“启用超级面板”，或把“鼠标按键弹出”改成其他按键）。

## 运行

```bash
cargo run -p devtools-hub --release
```

启动后只有菜单栏 / 托盘图标。macOS 按 ⇧⌘V 唤出面板（PasteNow 默认也用这个快捷键，两者同时运行时请在设置中改掉其中一个）；Windows 按 Alt+Shift+V。

常用参数：

```bash
cargo run -p devtools-hub -- --show --data-dir /tmp/dth-dev
```

- `--show`：启动后立即显示面板
- `--data-dir <目录>`：使用指定的数据目录（也可以用环境变量 `DEVTOOLS_HUB_DATA_DIR`），开发调试时不会污染真实数据
- `--pasteboard <名称>`：监听一个私有的命名剪贴板，不影响系统剪贴板（仅 macOS）

### Windows

需要 Rust 的 MSVC 工具链（安装 Visual Studio Build Tools 的 “使用 C++ 的桌面开发”，SQLite 和 zstd 需要 C 编译器）。

- debug 构建会保留控制台窗口，方便查看日志；release 构建不会弹出控制台
- 系统不允许普通权限的程序向“以管理员身份运行”的窗口发送按键（UIPI），粘贴到这类窗口时内容只会写入剪贴板，需要手动 Ctrl+V

### 打包成 macOS .app

```bash
zsh scripts/bundle-macos.sh
```

会生成 `target/release/DevTools Hub.app`（`LSUIElement`）。默认是临时（ad-hoc）签名；设置 `MACOS_SIGN_IDENTITY` 后用证书签名，见下文“macOS 签名”：

```bash
MACOS_SIGN_IDENTITY="DevTools Hub Self-Signed" zsh scripts/bundle-macos.sh
```

### macOS 权限

自动粘贴要模拟 ⌘V，需要在“系统设置 › 隐私与安全性 › 辅助功能”中授权。未授权时，选中条目只会复制到剪贴板，面板顶部会出现“去授权”按钮。

鼠标中键快捷面板同样需要这项权限（监听并拦截中键、模拟 ⌘C）。授权后几秒内自动生效，不用重启。

- 用 `cargo run` 启动时，系统会把权限算在启动它的终端上
- 打包成 .app 后，权限授予的是这个应用，系统按签名识别它：
  - 临时签名：只认这一次构建的代码哈希（cdhash）。重新打包、更新后就对不上了
  - 证书签名：认“Bundle ID + 证书”，重新打包、更新后权限仍然有效（见下文“macOS 签名”）

**系统设置里已经打开，应用却一直显示未授权**：授权记录属于签名不同的另一份构建（例如本地打的包和 dmg 里的包），两份的名字和 Bundle ID 一样，列表里只显示一项。这时点“去授权”，开关又会变成关闭。处理方法：在“辅助功能”列表中选中 DevTools Hub，点“−”删掉，再点“去授权”（或“+”添加 `/Applications/DevTools Hub.app`）重新打开。也可以先清掉这条记录：

```bash
tccutil reset Accessibility dev.devtoolshub.app
```

日志里能看到原因（zsh 自带一个同名的 `log` 命令，要写全路径）：`/usr/bin/log show --last 1h --predicate 'process == "tccd"' | grep -A2 "Failed to match existing code requirement"`，下面两行分别是记录里的和当前应用的 cdhash。

全局快捷键在 macOS 上使用 Carbon `RegisterEventHotKey`，在 Windows 上使用 `RegisterHotKey`，都不需要额外权限。

### macOS 签名

用一张固定的自签名证书签名，就不用每次更新后重新授权。证书只需要生成一次；换了证书，用户要重新授权一次，应用内更新也会拒绝签名证书不同的安装包。

1. 生成证书（用系统自带的 LibreSSL，有效期 20 年）：

   ```bash
   zsh scripts/create-signing-cert.sh
   ```

   默认输出到仓库外的 `~/.devtools-hub-signing/`：`devtools-hub-signing.p12`（证书和私钥）、`devtools-hub-signing.p12.b64`（base64）、`password.txt`（.p12 的密码）。这些文件包含私钥，请备份到密码管理器等安全的地方，不要提交到仓库

2. 在 GitHub 仓库的 Settings › Secrets and variables › Actions 中添加两个 Repository secret：

   | 名称 | 内容 |
   | --- | --- |
   | `MACOS_CERTIFICATE_P12` | `devtools-hub-signing.p12.b64` 的内容 |
   | `MACOS_CERTIFICATE_PASSWORD` | `password.txt` 的内容 |

   ```bash
   pbcopy < ~/.devtools-hub-signing/devtools-hub-signing.p12.b64
   ```

   发布流程会把证书导入一个临时钥匙串，用它签名，构建完删除钥匙串。没有配置这两个 Secret 时退回临时签名，并在构建日志中给出警告

3. 本地打包也想用同一张证书时，导入登录钥匙串（第一次签名时系统会询问是否允许 codesign 使用这把私钥，选“始终允许”）：

   ```bash
   security import ~/.devtools-hub-signing/devtools-hub-signing.p12 -k ~/Library/Keychains/login.keychain-db \
     -P "$(cat ~/.devtools-hub-signing/password.txt)" -T /usr/bin/codesign
   MACOS_SIGN_IDENTITY="DevTools Hub Self-Signed" zsh scripts/bundle-macos.sh
   ```

   生成证书时加 `--import` 可以一步完成导入

签名后可以这样检查，`designated =>` 一行应该是 `identifier "dev.devtoolshub.app" and certificate leaf = H"…"`，而不是 `cdhash H"…"`：

```bash
codesign --display --requirements - "/Applications/DevTools Hub.app"
```

说明：

- 从临时签名换成证书签名后的第一个版本，用户还要按上面的方法删掉旧记录、重新授权一次，之后的更新就不用了
- 自签名证书不受系统信任，没有经过苹果公证，第一次打开下载的 dmg 时仍会提示“无法验证开发者”，需要在“系统设置 › 隐私与安全性”中点“仍要打开”。要去掉这个提示需要 Apple Developer ID 证书并公证

## 检查更新与发布

应用通过 GitHub 接口 `GET /repos/zvae/devtools_hub/releases/latest` 获取最新的正式版本（草稿和预发布不会返回），把 `tag_name`（如 `v0.2.0`）与编译时的版本号（`Cargo.toml` 中的 `version`）比较：

- **自动检查**：启动 10 秒后检查一次，之后每天一次；按墙上时间判断是否到期，电脑睡眠过也会补上。自动检查失败时不提示，一小时后重试。可以在设置 › 通用中关闭
- **手动检查**：设置页底部的“检查更新”按钮，失败时显示原因
- **提示**：面板顶部出现“发现新版本”提示条（可以关掉，本次运行不再提示）；菜单栏 / 托盘菜单最上面出现“发现新版本 vX.Y.Z…”，点击打开设置页底部的更新信息，可以立即更新、查看更新说明或跳过此版本
- **网络**：使用系统自带的 TLS 与根证书（macOS Security.framework、Windows SChannel）；支持 `HTTPS_PROXY` 等环境变量，Windows 上还会读取系统代理设置

### 应用内安装

在 Release 的附件中按文件名结尾找当前平台的安装包（`-macos-arm64.dmg`、`-windows-x64.exe`），下载到临时目录，核对大小和 GitHub 记录的 SHA-256（附件的 `digest` 字段），然后：

| | macOS | Windows |
| --- | --- | --- |
| 替换 | `hdiutil attach` 挂载 dmg，核对 Bundle ID、版本号，`codesign --verify` 检查签名完整；`ditto` 复制到旧版本旁边，再把旧版本改名为 `.DevTools Hub.app.old`、新版本改名到原位置 | 正在运行的 exe 可以改名但不能覆盖：把它改名为 `devtools-hub.exe.old`，再把新版本写到原路径 |
| 重启 | shell 脚本等当前进程退出后 `open` 新版本（应用还在运行时 `open` 只会激活它） | 直接启动新版本 |
| 清理 | 新版本启动时删除 `.old` 和临时目录 | 同左 |

- 新版本带 `--after-update` 启动：等旧进程释放单实例锁，沿用同一个数据目录，启动后打开设置页并提示“已更新到 x.y.z”
- 下载可以取消；失败时显示原因，可以重试或改用浏览器下载
- 以下情况不支持应用内安装，“更新”按钮会变成在浏览器中下载：用 `cargo run` 等方式启动、不在 .app 里的程序；从下载目录直接打开、被系统移到只读位置运行（App Translocation）的应用；Release 中没有当前平台的安装包
- macOS 上当前版本是证书签名时，新版本必须满足同样的签名要求（同一张证书），否则拒绝安装：换了证书，系统会把新版本当作另一个应用，“辅助功能”权限失效。当前版本是临时签名时不检查，设置页会提示更新后需要重新授权
- 自己下载的文件不带隔离属性 / “来自网络”的标记，打开新版本时不会弹出 Gatekeeper 或 SmartScreen 提示

发布新版本：

1. 修改根目录 `Cargo.toml` 中的 `version`，合并到 `main`（第一次发布前先按“macOS 签名”配置好证书）
2. CI（`.github/workflows/release.yml`）会创建或更新 Release 草稿 `vX.Y.Z`，并上传 macOS 与 Windows 的安装包
3. 在 GitHub 上检查草稿并点“发布”。发布后，已安装的旧版本会在下一次检查时提示升级

注意：dmg 中 .app 的 `CFBundleShortVersionString` 必须与 Release 的标签一致（打包脚本从 `Cargo.toml` 读取），否则应用内安装会拒绝这个安装包。

## 构建产物与磁盘占用

`target/` 是 Cargo 的构建缓存，可以随时用 `cargo clean` 删掉，下次构建会重新生成。工作区的 `Cargo.toml` 已经针对体积做了配置：

- macOS 上 dev 构建默认 `split-debuginfo = "unpacked"`，每次增量编译都会在 `target/debug/deps` 留下一批新的 `.o` 文件且不会清理。这里改成了 `packed`，并且只给本项目代码保留行号信息，依赖不生成调试信息
- objc2-app-kit 只开启用到的类。默认特性会编译整个 AppKit，单个 rlib 就接近 180 MB
- release 构建会 `strip` 掉符号

调整前，几轮构建和测试后 `target/` 涨到了 8 GB；调整后，debug 构建 + 测试 + clippy 一共约 1.9 GB。`cargo test` 和 `cargo build` 因为开发依赖的特性不同，会各自编译一份 eframe/wgpu，这部分是 Cargo 的正常行为。

## 数据

目录见上面的平台差异表：

- `history.sqlite3`：SQLite（WAL），表 `items`、`payloads`、`lists`、`list_items`
- `blobs/`：压缩后超过 256 KB 的剪贴板数据（zstd）
- `settings.json`：设置

```

│   └── thumbnail.rs          图片缩略图
└── devtools-hub/             应用（macOS / Windows）
    ├── assets/               应用图标与托盘图标（原图及生成的各平台格式）
    ├── build.rs              Windows 上把程序图标嵌入 exe
    ├── monitor.rs            剪贴板监听线程
    ├── middle_click.rs       鼠标中键快捷面板的触发
    ├── selection.rs          模拟复制读取选中的内容，读完恢复剪贴板
    ├── tools/                中键面板里的功能：按选中内容匹配；json.rs 是 JSON 格式化、压缩、转义、路径过滤
    ├── hotkey.rs             全局快捷键
    ├── keys.rs               按键在界面上的写法（⌘ / Ctrl）
    ├── tray.rs               菜单栏 / 托盘图标
    ├── controller.rs         显示 / 切换面板
    ├── settings.rs           设置与数据目录
    ├── update.rs             检查 GitHub Releases 上的新版本，下载并安装
    ├── platform/
    │   ├── mod.rs            公共类型（面板位置、托盘区域）与平台文案
    │   ├── macos/            NSPasteboard、前台应用、CGEvent ⌘V / ⌘C、中键 CGEventTap、窗口与毛玻璃、LaunchAgent、替换 .app
    │   └── windows/          Win32 剪贴板、来源程序、SendInput Ctrl+V / Ctrl+C、中键鼠标钩子、窗口定位、图标提取、注册表开机启动、替换 exe
    └── ui/                   egui 面板、设置页、中键快捷面板、JSON 编辑器、字体、矢量图标与样式
```

两个平台的 `platform` 模块对外提供相同的模块和函数（`pasteboard`、`workspace`、`keyboard`、`mouse`、`panel`、`icons`、`login_item`、`updater`），编译时按目标系统选择其一。剪贴板面板、设置页、中键快捷面板和 JSON 编辑器共用同一个窗口，切换时由 `panel::show` 调整窗口大小和位置。

## 测试

```bash
cargo test --workspace
```

- 核心库的单元测试，包括 Windows 剪贴板格式转换（纯 Rust，任何平台都能运行）
- JSON 处理（格式化、保留数字与注释、错误位置、转义、路径过滤）与中键面板功能匹配的单元测试；macOS 上还在私有命名剪贴板上验证“模拟复制 → 读取 → 恢复剪贴板”
- macOS 上还有在私有命名剪贴板上的端到端测试：监听线程的记录、去重、隐私过滤、跳过本应用自己写入的内容、暂停。这些测试不会碰系统剪贴板
- Windows 上有程序图标提取的测试；剪贴板读写的往返测试会改写系统剪贴板，默认跳过：

  ```bash
  cargo test -p devtools-hub clipboard_round_trip -- --ignored
  ```

检查更新的单元测试不联网；访问真实 GitHub 接口、下载并校验最新安装包的测试默认跳过：

```bash
cargo test -p devtools-hub update::tests -- --ignored --nocapture
```

在 macOS 上可以对 Windows 实现做类型检查（只检查、不链接，不需要安装任何交叉编译工具）：

```bash
cargo check -p devtools-hub --features windows-typecheck
```

界面的离屏渲染测试需要 GPU，默认跳过，需要手动运行：

```bash
cargo test -p devtools-hub snapshot -- --ignored
```

它会用示例数据渲染面板、设置页、新版本提示、中键快捷面板和 JSON 编辑器（深色、浅色两套），截图输出到 `target/ui-snapshots/`，同时验证键盘选择、搜索、分类切换、打开设置，以及从快捷面板打开 JSON 编辑器、自动格式化、⌥C 压缩复制和关闭。

## 当前限制

- 只支持 macOS 和 Windows；在其他平台上编译后，运行只会输出提示
- Windows 版本只在 macOS 上做过类型检查，还没有在真实的 Windows 机器上运行验证
- 没有 iCloud 同步、智能列表的自定义规则、条目编辑、Quick Look
- 面板是 eframe 的普通窗口：弹出时会激活本应用，粘贴前再把焦点还给原来的应用。也因为这样，中键快捷面板要先读完选中内容再显示，没有选中内容时约 0.3 秒后才弹出（uTools 先不抢焦点地显示面板，再读取）
- 中键快捷面板开启后会拦截所有中键点击（与 uTools 相同），浏览器里中键打开新标签页等操作会失效；还没有按应用排除的设置
- 读取选中内容靠模拟复制：VS Code 等编辑器在没有选中时 ⌘C 会复制整行，这时会被当成选中了这一行
- JSON 编辑器还没有折叠 / 展开、转 XML / TypeScript，以及 URL Params、XML、YAML 自动转换
