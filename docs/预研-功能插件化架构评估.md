# 编译期工具模块化方案

> 更新日期：2026-11-25。本文包含目标设计和分阶段计划。当前分支已落地目录发现、通用运行时、JSON／时间戳／密码迁移、配置及热键入口；后台任务、跨工具协议和独立工具窗口仍按后续阶段推进。实际接口以代码及 [添加工具](添加工具.md) 为准。
>
> 采用“单个工具集合 crate + 目录模块 + Rust build.rs 自动发现”。基础改造完成后，使用已有依赖的普通工具只需新增自己的目录，正常执行 Cargo 命令即可接入，无需修改宿主、其他工具或中央注册表。

## 1. 目标与适用边界

### 1.1 新增工具的最终体验

以 Base64 工具为例，只增加：

```text
crates/devtools-tools/src/tools/base64/
├── mod.rs             # 描述符、工厂、输入匹配与动作声明
├── model.rs           # 本工具逻辑和状态；简单工具可合并到 mod.rs
├── ui.rs              # 界面与设置
└── tests.rs           # mod.rs 中按 cfg(test) 声明的行为测试
```

执行 `cargo check`、`cargo test` 或 `cargo run` 时，工具集合的 Rust `build.rs` 自动发现目录，生成模块引用和注册列表。宿主统一读取注册结果，工具自动进入目录、托盘及适用的中键匹配结果；设置、热键和窗口入口也由描述符驱动。

新增使用已有依赖的工具时，不改：

- `devtools-hub` 的清单、入口、页面状态、托盘、热键与设置页。
- 其他工具和共用图标枚举。
- 工具集合 `lib.rs`、`build.rs` 或手写注册列表。
- 根 workspace 成员列表及构建、CI、打包入口。

不为每个工具建立独立 `Cargo.toml`，不生成 Cargo 清单，不引入前置同步命令或额外语言运行时。

### 1.2 依赖管理的明确取舍

目录模块共用 `crates/devtools-tools/Cargo.toml`，没有各自独立的 Cargo 依赖图：

| 新增内容 | 需要修改的范围 |
|---|---|
| 使用现有依赖的新工具 | 只增加该工具目录 |
| 新工具需要新的第三方库 | 工具目录、工具集合 Cargo.toml、必要的 Cargo.lock 更新 |
| 复用已有领域 crate | 若工具集合已声明依赖，只增加目录；否则给集合清单增加一次依赖 |
| 提取新的独立领域 crate | 正常增加 crate 及 workspace／依赖声明，属于领域提取 |
| 新的通用宿主能力 | 演进公共 API 与对应平台适配，属于基础设施扩展 |

新第三方库可以直接在工具集合清单声明，不要求为其更新根 `workspace.dependencies`。目标专属依赖使用 target 依赖表，并克制启用 feature；所有工具的依赖特性遵循 Cargo 的正常统一规则。

“无需修改其他工具”仍然成立；“引入任意新依赖也绝不修改任何清单”不是本方案的承诺。这是保留原生 Cargo 工作流、取消构建前置生成的取舍。

### 1.3 保证范围

普通工具指使用已有模块协议和宿主能力的文本、文件、图像工具，以及协议已支持的共享页面或独立工具窗口。新增工具不要求宿主认识其业务概念。

全新窗口机制、系统权限能力或公共输入协议可能需要基础设施演进。仅某工具使用的原生实现优先留在该工具目录，按平台隔离，不要求加入宿主。

所有工具在编译时确定，重新编译应用后生效。模块化提供代码组织和接口隔离，不提供动态安装、热加载、进程隔离或独立 crate 的依赖隔离。

## 2. 当前基础与改造范围

当前共享主窗口有剪贴板、设置、快捷面板、JSON、时间戳、密码、OCR 七类页面。`Page::Search` 保留供离屏测试使用，生产搜索运行于独立视口。截图遮罩和贴图也是独立视口。

| 当前实现 | 已有价值 | 改造方向 |
|---|---|---|
| JSON、时间戳、密码工具 | UI、算法与测试已合并到各自目录 | JSON 用 core/ 分文件，密码和时间戳用私有 model；新增普通工具优先目录自包含 |
| `devtools-ui` | 字体、图标、样式、控件已共用 | 直接复用，不另建同职责基础库 |
| `devtools-search` / `core` | 已有服务、任务和宿主端口 | 用目录适配器接入，不重写搜索核心 |
| `HubApp`、`QuickAction` 及业务分派 | 共同修改面较大 | 通用运行时、稳定 ID、描述符驱动入口 |
| `Settings`、固定热键错误数组 | 当前行为明确 | 命名空间配置、按动作 ID 管理热键 |
| `snip/ocr.rs` | OCR 领域逻辑集中 | 按需提取复用，独立于普通工具接入 |

宿主继续管理剪贴板基础服务、原生窗口机制、托盘、更新和退出。剪贴板、设置、快捷面板首期可保留为宿主页；普通工具走一个通用路由，不逐工具添加 `Page` 变体。

基础改造一次性增加固定 crate、workspace 成员和宿主依赖，调整测试接入；CI 和打包仍使用原生 Cargo 命令。完成后以“只增加目录”持续验收。

## 3. 总体结构与依赖方向

```text
devtools-hub
  ├── devtools-module-runtime       # 通用管理、分派、surface 与生命周期
  ├── devtools-tools                # 手工维护的固定 crate
  │     ├── build.rs                # 自动发现目录，生成 Rust 引用
  │     └── src/tools/*/mod.rs       # 同一 crate 内的私有目录模块
  └── 宿主平台适配与基础服务

devtools-tools
  ├── devtools-module-api           # 描述符、实例接口、输入、宿主端口
  ├── devtools-ui                   # 共用 UI
  └── 已有领域 crate / 新工具共用依赖

devtools-module-runtime → devtools-module-api / devtools-ui
devtools-module-api     → egui / serde / 必要的基础数据类型
```

箭头表示 Cargo 依赖方向。API、运行时、领域库不依赖宿主或具体工具。工具集合对外只暴露注册结果，不公开工具目录或具体实例类型。

| 层 | 职责 | 禁止包含 |
|---|---|---|
| `devtools-module-api` | 协议、描述符、宿主端口、公共输入输出 | 具体工具枚举、工厂列表、平台实现 |
| `devtools-module-runtime` | 注册校验、实例、导航、通用窗口和任务协调 | 具体工具业务分支 |
| `devtools-tools` | 共用依赖清单、目录发现、对外注册入口 | 工具专属中央分派和跨工具可变状态 |
| `src/tools/<name>` | 自身动作、状态、UI、配置和任务 | 引用宿主或其他工具私有实现 |
| `devtools-hub` | 注入原生能力、装配运行时、eframe 生命周期 | 普通工具专属字段及入口分支 |

同一 crate 内的工具没有 Cargo 级隔离。使用私有工具模块、最小可见性与依赖规则检查约束互引；共享逻辑放在集合的公共支持目录或领域 crate，跨工具动作经运行时路由，不直接访问兄弟模块。不能声称 `cargo tree` 可以检查目录模块之间的依赖。

## 4. Rust build.rs 自动发现与注册

### 4.1 固定目录与构建流程

```text
crates/devtools-tools/
├── Cargo.toml                     # 固定依赖清单
├── build.rs                       # Rust 编写，使用标准库完成目录扫描
└── src/
    ├── lib.rs                     # 固定的生成文件 include 入口
    ├── support/                   # 共用辅助逻辑，按需设置
    └── tools/
        ├── timestamp/mod.rs
        ├── password/mod.rs
        ├── json/mod.rs
        └── base64/mod.rs          # 新增工具仅增加此目录及内部文件
```

根 workspace 一次性加入工具集合、API 与运行时；宿主一次性声明固定依赖。之后工具目录不是 workspace 成员，不需要单独清单，也不涉及修改 Cargo 依赖图。

构建路径：

```text
cargo check/build/test/run
  → Cargo 按固定清单解析依赖
  → 编译并运行 devtools-tools/build.rs
  → 在 OUT_DIR 生成 tools_registry.rs
  → lib.rs 引入生成代码，编译全部工具目录
  → 宿主读取描述符并按需创建工具实例
```

生成 Rust 模块是 Cargo 支持的构建脚本用途；输出只写入 `OUT_DIR`，不重写源码或 Cargo 清单。见 [Cargo 构建脚本文档](https://doc.rust-lang.org/cargo/reference/build-scripts.html)。

### 4.2 目录约定与固定入口

- 扫描 `src/tools/` 的直属子目录，每个目录必须有 `mod.rs`；缺失就报错，不静默忽略。
- 目录名使用小写字母开头，后续只用小写字母、数字和下划线；生成内部名称统一加前缀，避开关键字冲突。
- 普通文件不作为工具；辅助代码放在工具内部或 `src/support/`，不混入发现根目录。
- 每个工具的 `mod.rs` 提供 `pub(super) fn descriptor() -> ModuleDescriptor`，自身通过正常 `mod model; mod ui;` 引用内部文件。
- 模块 ID、API 版本、平台可用性、动作和工厂均在 Rust 描述符声明一次。目录名只用于源码组织，不作为持久化身份。
- 工具目录中不允许再放 Cargo.toml；需要独立领域库时移到领域 crate，而非让 build.rs 解析和合并依赖。

固定 `lib.rs` 入口示意：

```rust
include!(concat!(env!("OUT_DIR"), "/tools_registry.rs"));
```

生成文件的形态如下，具体路径仅为示意：

```rust
#[path = "/checkout/crates/devtools-tools/src/tools/base64/mod.rs"]
mod tool_base64;

pub fn registrations() -> Vec<devtools_module_api::ModuleDescriptor> {
    vec![tool_base64::descriptor()]
}
```

生成文件在 crate 根部展开；工具子模块的 `pub(super)` 描述符可被该注册函数访问，宿主只能看到公开的注册结果。`#[path]` 指向真实 mod.rs，因此内部子模块和嵌入资源相对原始源码定位。

### 4.3 生成算法、增量编译与诊断

`build.rs` 使用标准库完成以下步骤：

1. 从 `CARGO_MANIFEST_DIR` 定位工具根目录，从 `OUT_DIR` 定位输出；不依赖当前 shell 的工作目录。
2. 枚举并校验工具目录，拒绝越界或符号链接目录，检查入口文件，按目录名排序。
3. 为所有工具生成私有模块声明，以及对描述符函数的显式引用。不解析 Rust 源码、业务配置或第三方依赖。
4. 用正确的 Rust 字符串转义写入路径，覆盖 Windows 反斜杠、空格和 Unicode；路径无法可靠表示时明确报错，禁止静默 lossy 转换。
5. 先计算完整内容；没有变化不重写，变化时一次完整写入 OUT_DIR。每个构建目标的输出交给 Cargo 管理，不共用源码目录下的临时注册文件。
6. 为 build.rs 和整个 `src/tools/` 发出 `cargo:rerun-if-changed`，捕获目录新增、删除、改名及内部资源变化；不能只监听上次发现的文件。

生成物可以包含本地绝对源码路径，只用于当前 checkout 的编译，不提交、不复制到其他检出目录。确定性要求是在相同输入和路径下输出一致，不加入时间戳或随机排序；发布产物的路径隐私按需要用编译器路径映射处理。

编译器负责报告描述符缺失、签名错误和工具内部类型错误。描述符是 Rust 值，生成器不冒充 Rust 解析器：ID 重复、动作冲突、非法窗口规格由通用注册校验器验证，并纳入自动测试及启动校验。

注册表可在应用初始化时构建，但它只收集描述符；工具实例仍然按需创建。release 构建通过显式函数引用保留注册项，验证时检查实际工具集合。

### 4.4 平台处理

生成器不按主机平台跳过目录，对所有工具生成相同的模块引用。工具内部用 `#[cfg(target_os = "macos")]` / Windows 条件隔离实现，平台专属依赖写在工具集合的 target 依赖表中。

每个工具在两种支持平台上都须有可编译的描述符入口。仅支持单平台的工具，在其他平台提供不可用描述符及受控的不可用工厂，运行时隐藏入口；不能让生成代码引用缺失函数。平台可用性在目标代码中判断，不在 build.rs 中误用主机的 cfg。

`cargo test --workspace` 编译的是固定工具集合；平台相关测试也在工具内部按 cfg 隔离。公共 API 保持平台中立，Windows 类型检查与真实 Windows CI 各自覆盖对应范围。

### 4.5 原生 Cargo、IDE、格式化与发布

```bash
cargo check --workspace
cargo test --workspace
cargo test -p devtools-tools
cargo run -p devtools-hub --release
```

干净检出直接运行以上命令，Cargo 自动执行 build.rs，不需要同步、生成清单或更换打包入口。`--locked` 与离线模式仍按正常依赖约束执行。

IDE 使用正常 Cargo workspace。自动发现的模块依赖构建脚本输出，需启用构建脚本分析；新增／删除目录后如 IDE 未自动刷新，重新加载 workspace，而非运行前置生成器。

`cargo fmt` 的目录覆盖不能想当然依赖 OUT_DIR 中的 include。阶段 A 必须验证新目录是否被 rustfmt 发现；若未覆盖，在固定的 CI 格式检查中遍历工具目录调用 rustfmt，新增目录自动纳入，不能逐工具维护格式文件列表。它仅补充格式检查，不包装构建，也不修改注册机制。

首期直接生成注册列表，已有自动发现能力，无需另加 inventory、linkme 或自定义注册宏。未来若换用链接期注册，仍须保留模块进入编译的机制，不能把注册宏当成目录扫描。

### 4.6 最小机制验证记录

2026-11-25 在 macOS、Rust 1.98 的临时无依赖 crate 中验证了上述生成方式：OUT_DIR 引入真实 mod.rs、`pub(super)` 描述符、内部子模块和测试均可编译；不执行 clean，新增及删除目录分别使注册数量从 1 变为 2、再变回 1；检出路径包含空格和中文。临时验证文件未加入项目。

该验证只确认代码生成与 Cargo 目录变化检测的基本可行性，不代表模块运行时、真实 UI、Windows、MSRV 1.95 或格式化覆盖已通过。其余行为按第 12 节在实施阶段验收。

## 5. 一份描述符驱动所有入口

一个模块可有多个动作，例如 JSON 的“打开编辑器”和“格式化并复制”。全局动作身份为 `(ModuleId, LocalActionId)`，不在宿主增加业务枚举变体。

| 声明 | 驱动行为 |
|---|---|
| 名称、说明、别名、分类、展示顺序 | 工具目录、名称搜索和菜单 |
| 模块自带图标或绘制回调 | 快捷面板、标题栏、工具列表 |
| 动作局部 ID、名称、输入要求、入口可见性 | 托盘、中键、热键和跨工具调用 |
| 有预算的输入匹配回调 | 按选区对动作评分和排序，不构造实例 |
| 默认热键 | 通用热键设置项和冲突提示 |
| 默认页面／窗口规格 | 尺寸、位置偏好、边距及失焦策略 |
| 配置版本、默认值、迁移和校验入口 | 通用存储与私有强类型配置 |
| 工厂、启用策略、实例保留策略 | 按需创建及资源回收 |

描述符在启动时构建一次，不启动线程、读取业务文件、访问剪贴板或分配大型状态。匹配回调只做受限内存判断；文件存在性、内容解析等放在动作激活后完成。

图标允许模块自带矢量绘制函数或嵌入资源，不要求修改 `devtools-ui::Icon`。显示顺序由声明和稳定 ID 决定，不依赖目录枚举顺序。

运行时在创建实例前校验重复模块 ID、动作 ID、API 版本、窗口规格和保留 ID 冲突。模块 ID 和动作 ID 在各工具的 Rust 描述符中定义，是持久化身份；目录改名可保持 ID 不变，ID 改名须有迁移声明。

## 6. 模块接口与宿主交互

以下为接口草图，省略 DTO 完整定义；实施时通过真实模块试点收敛签名：

```rust
pub trait ToolModule {
    fn activate(&mut self, request: Activation, ctx: &mut ModuleCtx<'_>) -> ModuleUpdate;
    fn render(&mut self, ui: &mut egui::Ui, ctx: &mut ModuleCtx<'_>) -> ModuleUpdate;
    fn update(&mut self, event: ModuleEvent, ctx: &mut ModuleCtx<'_>) -> ModuleUpdate;
    fn window_policy(&self) -> WindowPolicy;
    fn settings_ui(&mut self, ui: &mut egui::Ui, ctx: &mut ModuleCtx<'_>) -> ModuleUpdate;
}
```

实例只在 UI 线程使用，不强制 `Send + Sync`。工厂返回 `Result<Box<dyn ToolModule>, ModuleError>`；失败时显示模块错误，其他工具继续可用。生命周期接口服务于静态内置模块，不表示动态加载。

`ModuleCtx` 仅提供模块限定配置、任务接口和只读环境，不暴露 `HubApp`、`Shared`、可变注册表或具体工具状态。

`ModuleUpdate` 返回强类型宿主请求：提示、复制、文件对话框、激活动作、调整固定状态、关闭当前 surface 等。复制区分普通与敏感内容，保留密码现有的隐私标记及跳过历史行为。

主线程能力与后台能力分开：窗口、焦点、模态菜单等由宿主执行；后台计算、文件读取、解码通过安全句柄与任务设施使用，不把整个平台接口都标成 `Send + Sync`。对话框请求携带发起 surface 身份，恢复焦点和层级按该窗口处理。

借用与执行顺序固定为：

```text
取出目标实例 → 调用模块回调 → 放回实例
→ 顺序执行返回的宿主请求 → 调度后续模块事件
```

绘制过程中不立即打开其他模块，不递归借用注册表。每轮动作数量有预算，连续导航转到后续轮次，防止工具互相激活形成循环。运行时与原生适配分别持有状态，避免用 `&mut HubApp` 包揽所有能力。

## 7. 输入与跨工具调用

公共输入首期覆盖空输入、文本、文件路径列表和共享图像；文本和图像用共享所有权避免导航复制。输入描述数据，不包含 JSON、时间戳、Base64 等工具专属变体。

`Activation` 包含目标动作、输入、来源、请求 ID 和打开意图。来源区分中键、托盘、热键、工具目录及其他模块；托盘直接打开工具不得复用上次中键选区。

接收模块自己校验输入，并决定保留草稿、替换内容或创建窗口。文件超限、格式不合法等由模块返回可显示错误，宿主不解析业务内容。

| 调用 | 输入 | 宿主只需处理 |
|---|---|---|
| 中键 → JSON / 时间戳 | 文本或路径 | 目标动作、来源、窗口意图 |
| 截图 / 贴图 → OCR | 共享图像 | 图像预算、目标 surface |
| 文本转换 → 另一个文本工具 | 文本 | 请求 ID 与导航 |
| 工具目录 → 任意工具 | 空输入 | 默认动作 |

跨工具调用通过通用 `ActivateAction { target, input, request_id }` 请求，负载为公共输入类型，不把任意对象藏进 `Any` 或 JSON。目标缺失、被禁用、当前平台不支持或输入不匹配时返回明确错误。

专用工作流确需结构化输入时，可建立独立领域协议 crate，由调用方、提供方共同依赖，并提供到公共传输类型的明确适配。超出当前表达能力时演进公共协议，不开无类型后门。现有贴图编辑的 ID、坐标和回写流程，在专门协议迁移前保留原有强类型调用。

新增普通工具无需扩大 `AppEvent`。跨线程系统唤醒继续用有限宿主事件，模块结果按实例与任务身份路由。

## 8. Surface、状态与后台任务

### 8.1 普通页面与独立工具窗口

| 类型 | 用途 | 分工 |
|---|---|---|
| 共享主窗口页面 | 时间戳、密码、JSON 等 | 模块画内容，宿主管尺寸、位置、焦点、隐藏 |
| 独立工具窗口 | 搜索等常驻工具 | 通用窗口宿主管 viewport，模块拥有业务状态与内容 |

宿主用 `Tool { module_id, instance_id, surface_id }` 路由。新增工具通过描述符选择已支持的类型，不增加工具专属页面变体。

默认规格包括初始／最小尺寸、位置、边距、标题栏模式、toast 安全区域；运行策略包括固定、失焦隐藏、可见性及脏状态。失焦行为综合模态保护、宽限期和 surface 状态，不简化成一个静态布尔值。

独立窗口延迟回调不能借用 `&mut HubApp` 或已移走的实例。通用 surface driver 持有窗口可共享状态句柄，回调产生动作，再由运行时消费。搜索适配阶段须实证该模型兼容 eframe 延迟视口。

截图遮罩和多实例贴图首期保留专门宿主。透明唤醒、关闭时序、编辑回写和多实例生命周期单独设计，不作为普通工具零接线的前置条件。

### 8.2 生命周期与任务预算

- 注册描述符不等于创建实例；首次激活或打开私有设置时按需创建。
- 启用开关控制入口和实例，不能卸载已链接代码；禁用后保留配置。
- 重复打开策略由模块声明：复用、替换输入或新建 surface，普通工具默认复用。
- 隐藏时可保留草稿、释放缓存，敏感结果可声明清理。
- 隐藏实例仍接收任务完成事件，不每帧轮询未使用工具。
- 每次输入有代际，每个实例有身份，迟到结果不能覆盖新输入或新实例。
- 退出先禁止新动作，再取消任务、保存状态和等待结束；所有等待共用截止时间。

普通工具通过共享任务设施提交有界任务，不自行无约束地创建线程池。设施按模块、实例分组，提供优先级、取消和唤醒；模块保留私有结果接收器，宿主不识别业务结果类型。

长扫描、交互计算和解码分配不同预算，防止长任务挤占输入与可见行。平台不可取消调用有明确退出策略，禁止用无超时等待阻塞主线程。

## 9. 配置、热键与通用入口

### 9.1 配置命名空间

```json
{
  "version": 2,
  "global": {},
  "modules": {
    "devtools.json": {
      "version": 1,
      "enabled": true,
      "settings": { "indent": "Four" },
      "window": { "size": [760, 560] },
      "hotkeys": {}
    }
  }
}
```

版本数字仅示意，正式迁移时确定。全局存储负责原子写入、合并、防抖、错误反馈及退出刷新；模块负责自身强类型配置、默认值、校验和迁移。工具只提交自己的命名空间，不能覆盖其他模块或整个文件。

必须保证：

1. 顶层和模块分别有版本；不可理解的较新版本只读保留。
2. 未编译、未启用模块的完整配置原样往返。
3. 已知模块内部的未知字段也保留，使用原始 JSON 底稿与显式字段合并，或保留扩展字段的模型。
4. 单模块损坏只影响自身；默认值用于运行，不自动覆盖损坏原值。
5. 迁移失败保留原始值，提供诊断；明确修复或重置后才能替换。
6. 保存失败可见，能区分运行配置与已落盘配置，不显示虚假成功。
7. ID 改名有迁移声明，不以新模块身份丢失旧配置。

现有 JSON 缩进、工具尺寸等只在一次性迁移器中映射。搜索独立配置先由适配器管理，统一存储具备等价保护后再迁移，不同时维护两套权威设置。

### 9.2 热键与入口

宿主维护 `ActionId → 热键／配置／错误` 映射，工具只声明默认值，通用设置页遍历注册表绘制。

- 冲突时显示双方模块和动作，不静默抢占，支持调整或禁用。
- 面板开关、系统退出使用宿主保留命名空间。
- 托盘、中键、工具目录、最近使用、收藏共用同一注册表。
- 禁用工具统一注销入口、热键并处理任务，保留配置。
- 中键面板高度有上限并可滚动，支持名称／别名搜索，数字键只作用于当前显示的前九项。

## 10. 新增与删除工具的流程

1. 新建 `crates/devtools-tools/src/tools/<name>/mod.rs`，实现描述符、工厂和模块接口。
2. 在自己的目录组织逻辑、UI、图标、动作、匹配、设置和测试，不编辑中央模块声明。
3. 优先复用工具集合已声明的依赖；若有新依赖，只更新集合 Cargo.toml 及必要锁文件。
4. 执行 `cargo check -p devtools-tools` 和相关测试，再验证实际界面入口与行为。
5. 使用已有依赖时只提交自己的目录；不提交 OUT_DIR 中的生成物。

无需修改宿主、其他工具、集合 lib.rs、build.rs、QuickAction、Page、托盘列表或热键枚举。删除目录后下一次 Cargo 构建自动移除注册项；配置保留，失效收藏和热键显示不可用。仍有其他工具引用其私有实现时应视为架构违规，而非要求补回中央注册。

## 11. 分阶段实施与验收

### 阶段 A：目录发现与真实轻量工具

建立固定工具集合、API 和最小运行时；一次性接入 workspace、宿主固定依赖和通用路由。Rust build.rs 只生成模块声明与注册代码。迁时间戳状态和 UI，核心逻辑归入同目录的 core 或 model，打通托盘、中键、固定／失焦、复制；同时确认 IDE 和格式检查覆盖。

验收：干净检出直接用原生 Cargo 构建；增删一个使用已有依赖的临时工具目录，注册与入口自动变化，宿主、运行时、生成器及其他工具零改动；测试应用间无状态共享。

### 阶段 B：配置、任务与 JSON／密码

实现命名空间配置、迁移、版本保护、取消、输入代际和隐藏唤醒。迁 JSON 与密码，验证文件输入、大文本后台处理和敏感复制；删除宿主中对应字段、分支及业务配置。

验收：旧配置、未知字段、保存失败、迟到任务、退出预算及 UI 行为通过；再加普通工具不需要扩展公共 API 或中央入口。

### 阶段 C：工具目录与独立窗口

完成名称搜索、最近使用、常用工具和通用设置入口。工具集合通过 search 目录适配器引用现有搜索 crate，保留索引与服务；按需提取 OCR 领域逻辑后迁 OCR 页面。清理普通工具专属事件。

验收：新增独立窗口工具只改自身目录；搜索普通／浮动／固定模式、焦点、最小化和关闭保持；主窗口隐藏时截图与贴图唤醒无回归。

### 阶段 D：复杂视口与宿主页

有明确收益时再迁截图、贴图或剪贴板页面。先验证多实例视口和编辑回写协议，不把它作为普通工具自动接入的前置条件。

每阶段交付可用版本，完成真实试点后再估计后续工时，不机械迁移所有页面。

## 12. 验证与最终完成标准

### 12.1 自动发现与构建

- 临时 checkout 中使用现有依赖仅新增工具目录，干净 `cargo check/test/build --release` 均自动发现，无预生成或初始化步骤。
- 连续添加、删除、重命名工具目录，不清理 target 也能更新注册表；工具内部资源变化会触发正确重建。
- 目录缺入口、非法目录名、越界路径、错误描述符签名有明确诊断；重复 ID／动作与不兼容 API 由注册校验测试及启动校验发现。
- 同输入同路径下输出一致，不变化不重写；生成物只在 OUT_DIR，不改清单或源码。
- 验证带空格、中文和 Windows 路径；模块内子模块与嵌入资源相对真实源码解析。
- 验证两平台 cfg、target 依赖、release 注册保留、locked、离线、IDE 和格式检查。
- 验证新依赖只更新集合清单及锁文件，宿主和其他工具无接线改动。

### 12.2 行为与兼容

- 中键、托盘、热键和跨工具输入不串用历史选区。
- 隐藏、重开、禁用、启用、重复创建应用无状态泄漏。
- 尺寸、固定、失焦、模态恢复、toast 和键盘交互保持。
- 普通与敏感复制正确区分，测试不碰用户系统剪贴板。
- 配置保留未知模块及未知字段，失败不覆盖原值。
- 验证任务取消、旧结果丢弃、隐藏接收结果和退出截止时间。

### 12.3 边界、依赖与性能

Cargo 层禁止工具集合依赖 hub 或运行时，API 和领域库不反向依赖集合；目录层禁止工具互相引用私有实现。目录规则用源码规则检查和代码审查约束，Rust 可见性只提供部分保护，不等价于独立 crate 隔离。

所有目录模块共享依赖与编译单元，新工具可增加编译时间和二进制大小，不能承诺按工具增量隔离。工具数量或依赖冲突确实造成问题时，再单独评估提取领域 crate；不因此恢复日常中央注册。

实例按需创建，未打开工具不启动线程或周期重绘。记录改造前后启动、空闲内存、首次打开、输入反馈、退出和编译耗时；大 JSON、搜索、长截图、多贴图单独验证，不把搬迁视作性能修复。

执行 workspace 检查与测试；涉及 Windows 适配时执行类型检查和 Windows CI；涉及界面时重跑相关快照并人工确认。

最终标准：在既有协议与依赖范围内，文本工具、带设置和任务的文件工具、独立窗口工具各新增一个，只增加各自目录，原生 Cargo 自动接入所有声明入口，宿主和其他工具零修改。新依赖只走集合清单的显式维护流程。

## 13. 必须避免的实现偏差

| 偏差 | 为什么不符合方案 |
|---|---|
| 每加目录还要改 lib.rs 或手写工厂列表 | 没有实现自动发现 |
| 为每个工具增加独立 Cargo.toml | 改回独立 crate，依赖发现问题重新出现 |
| 用 build.rs 合并或修改 Cargo 清单 | 超出源码生成职责，破坏固定依赖图 |
| 生成代码写回 src 或仓库根目录 | 污染源码，增加并发和清理成本 |
| 只监听已有文件，不监听发现根目录 | 新增、删除可能留下旧注册表 |
| 声称新第三方依赖也无需更新清单 | 混淆目录模块和独立包的依赖边界 |
| 只注册 render | 菜单、热键、配置、窗口仍需人工接线 |
| ModuleCtx 暴露 HubApp 或兄弟工具状态 | 原有耦合仍然存在 |
| 提前创建所有实例、每帧轮询 | 空闲开销随工具数增长 |
| 各工具随意新建线程池 | 并发、优先级、退出预算失控 |
| 用 Any 或 JSON 隐藏任意业务对象 | 输入协议和诊断边界不清 |
| 强行把截图和贴图改成普通页面 | 忽略多实例视口和焦点生命周期 |

## 14. 设计决策摘要

1. 使用固定 `devtools-tools` crate，工具是其内部目录模块，不是独立 Cargo 包。
2. Rust build.rs 自动生成模块引用和注册列表，正常 Cargo 命令即可构建，无前置同步或额外运行时。
3. 使用已有依赖只加工具目录；新依赖更新工具集合清单，宿主和其他工具无需修改。
4. 描述符统一驱动图标、匹配、菜单、热键、设置和窗口，实例按需创建。
5. 回调结束后执行宿主请求，任务按实例和代际处理；复用 UI 基础，小型工具算法与测试放在自身目录。
6. 用仅增删工具目录的行为验证持续守住自动接入边界，复杂视口分阶段演进。
