# 微信截图：滚动截图与文字提取实现分析

分析对象：本机 `/Applications/WeChat.app`，版本 4.1.15（`CFBundleShortVersionString`），通用二进制（x86_64 + arm64），只看 arm64 版本。

分析方法只用了静态手段加本机进程信息：`otool -L`（链接库）、`dyld_info -imports` / `nm -u`（导入符号）、`nm -gU`（导出符号）、`strings`（Qt 类名、ObjC 选择子、日志与打点字段）、
`objdump -d`（只反汇编了下文提到的几个函数）、`ps`（进程启动参数）以及磁盘上的模型文件。文中地址都是 `libwxocr.dylib` arm64 切片里的虚拟地址。
“推断”标出的地方没有逐条还原汇编，是根据调用关系得出的结论。

## 1. 总体形态

| 结论 | 证据 |
| --- | --- |
| `MacOS/WeChat`（182 KB）只是加载器，代码在 `Resources/wechat.dylib`（357 MB） | `MacOS/WeChat` 只链接 `@rpath/libwxld.dylib` 和系统框架；`find -size +10M` 中最大的是 `Resources/wechat.dylib` |
| 截图模块是 Qt 写的，命名空间 `weshot` | `strings`：`weshot::WeShot`、`weshot::ScreenShoter`、`weshot::LongScreenShoter`、`weshot::GrabWorker`、`weshot::OpenCVWorker`、`weshot::SpliceWorker`、`weshot::WeShotLongScreenshotmenu`、`weshot::AiMosaicButton` 等（Qt moc 元数据中的类名）；同时有 `QtMeta`、`QObject` 等 Qt 字符串 |
| 图像算法与 OCR 在 `Resources/libwxocr.dylib`（58 MB） | `otool -L wechat.dylib`：`@rpath/libwxocr.dylib`；`libwxocr` 导出 1681 个 `cv::` 符号（静态链接 OpenCV）、`xnet::dnn` 推理引擎、`ClipperLib`、`wx_qbar_export::QBar`（扫码） |
| 不用 Apple Vision | 两个库的 `otool -L` 都没有 `Vision.framework`；`strings` 中没有 `VNRecognizeTextRequest`、`VNImageRequestHandler`、`ImageAnalyzer` |

## 2. 滚动截图（长截图）

### 2.1 取帧：ScreenCaptureKit，并排除自己的窗口

| 结论 | 证据 |
| --- | --- |
| 用 ScreenCaptureKit 取屏幕画面 | `otool -L wechat.dylib`：`ScreenCaptureKit.framework (weak)`；`nm -u`：`_OBJC_CLASS_$_SCStream`、`SCStreamConfiguration`、`SCContentFilter`、`SCShareableContent`、`SCScreenshotManager`，以及 `_SCStreamFrameInfoDirtyRects`、`_SCStreamFrameInfoContentRect` 等 |
| 截图模块有自己的 SCK 抓取器 | C++ 类型编码：`weshot::sck_grabber::CaptureLifecycle`（含 `start_state_` / `stop_state_` 原子状态） |
| 连续取帧并把自己的窗口排除在外 | ObjC 选择子：`initWithDisplay:excludingWindows:`、`initWithFilter:configuration:delegate:`、`addStreamOutput:type:sampleHandlerQueue:error:`、`setMinimumFrameInterval:`、`stream:didOutputSampleBuffer:ofType:`、`startCaptureWithCompletionHandler:`；另有 `setSharingType:` |
| 旧系统上回退到 CoreGraphics | 同时导入 `_CGDisplayCreateImageForRect`、`_CGWindowListCreateImage`、`_CGWindowListCreateImageFromArray`（ScreenCaptureKit 是弱链接，旧系统上不存在也能启动） |

### 2.2 流水线：取帧 → 算偏移 → 拼接

| 结论 | 证据 |
| --- | --- |
| 三个工作对象各管一段 | `weshot::GrabWorker`（取帧）、`weshot::OpenCVWorker`（算偏移）、`weshot::SpliceWorker`（拼接），由 `weshot::LongScreenShoter` 驱动 |
| 每段都有耗时打点 | 相邻字符串：`grab_assign_time`、`get_offset_time`、`maintain_cur_time`、`opencv_tot_time`，以及日志 `long_shot_test.cid : %_, %_ : %_`、`StartLongScreen`、`grab_target_rect` |

### 2.3 偏移计算：ORB 特征点 + 汉明距离暴力匹配

`wechat.dylib` 从 `libwxocr.dylib` 只导入了**一个**符号，就是拼接偏移：

```
$ dyld_info -arch arm64 -imports wechat.dylib | grep libwxocr
      0x0286  _GetMergeOffsetInner  (from libwxocr)
```

反汇编 `_GetMergeOffsetInner`（`0x1318b58`–`0x13199cc`）及其旁边的辅助函数：

```
; 辅助函数 0x13189b4 内
13189f4  mov  w8, #0x999a ; movk w8, #0x3f99, lsl #16 ; fmov s0, w8   ; scaleFactor = 0x3f99999a = 1.2f
1318a04  mov  w0, #0x7d0        ; nfeatures     = 2000
1318a08  mov  w1, #0x8          ; nlevels       = 8
1318a0c  mov  w2, #0x1f         ; edgeThreshold = 31
1318a10  mov  w3, #0x0          ; firstLevel    = 0
1318a14  mov  w4, #0x2          ; WTA_K         = 2
1318a18  mov  w5, #0x0          ; scoreType     = HARRIS_SCORE
1318a1c  mov  w6, #0x1f         ; patchSize     = 31
1318a20  mov  w7, #0x14         ; fastThreshold = 20
1318a24  bl   cv::ORB::create(int, float, int, int, int, int, cv::ORB::ScoreType, int, int)

; _GetMergeOffsetInner 内
1318ea0  mov  w1, #0x6          ; normType  = NORM_HAMMING
1318ea4  mov  w2, #0x0          ; crossCheck = false
1318ea8  bl   cv::BFMatcher::BFMatcher(int, bool)
1318ef4  mov  w4, #0x5          ; k = 5
1318ef8  bl   cv::DescriptorMatcher::knnMatch(...)
```

辅助函数里还调用了 `cv::cvtColor`（转灰度）、`cv::Mat::Mat(const Mat&, Rect)`（取 ROI）。ORB 参数除了特征点数从默认的 500 提到 2000，其余都是 OpenCV 默认值。

推断的算法：在上一帧和新一帧（灰度、限定在选区内）上提取 ORB 特征点，用汉明距离 kNN 匹配，从匹配对的纵向位移中统计出两帧之间的滚动距离，`SpliceWorker` 再把新露出的部分接到长图下方。

### 2.4 滚动由用户完成，微信不模拟滚轮

| 结论 | 证据 |
| --- | --- |
| 不合成滚轮事件 | 导入表里没有 `CGEventCreateScrollWheelEvent` / `CGEventCreateScrollWheelEvent2`（只有 `CGEventCreateMouseEvent`、`CGEventCreateKeyboardEvent`、`CGEventPost`） |
| 让滚轮落到下面的窗口（推断） | 选择子 `setIgnoresMouseEvents:`、`scrollingDeltaY`、`CGEvent`；导入 `CGEventTapCreateForPid`。即选区内鼠标穿透，或者把收到的滚轮事件转发出去。没有在界面上逐项实测 |

## 3. 文字提取（OCR）

### 3.1 OCR 跑在单独的进程里

运行中的微信有一个专门加载 `libwxocr.dylib` 的辅助进程（`ps -axo command`，节选）：

```
WeChatHelper.app/Contents/MacOS/WeChatHelper ... --target-spec={..."primary_name":"libwxocr.dylib","process_type":"wxocr",
  ..."work_path":".../app_data/magicdy/targets/wxocr"}
```

| 结论 | 证据 |
| --- | --- |
| `libwxocr.dylib` 是子进程的入口 | 导出 `_WeChatMain`；链接 `@rpath/libmmmojo.dylib`（Chromium Mojo 进程间通信） |
| 主进程是 OCR 服务的客户端 | `wechat.dylib` 字符串：`ocr-resource-root`、`TryStartOCR`、`OCRClientService`、`OnRemoteDisconnect`、`ocr_serv`、`std::shared_ptr<kernel::manager::OCRResult>` |
| 独立日志 | `~/Library/Containers/com.tencent.xinWeChat/Data/Documents/app_data/log/LD_wxocr_*.xlog` |
| 界面 | `mmui::PreviewOcrPanel`、`mmui::OcrPanelAnimator`、`OpenOcrPreview` |
| 还有网络 OCR 模式 | 字符串：`do net mode ocr`、`net ocr upload`、`net ocr reg fail` |

### 3.2 自研推理引擎 + 自带模型

`Resources/` 下的模型（`ls -la`）：

| 文件 | 大小 | 用途 |
| --- | --- | --- |
| `text_det_fp16_v2.xnet` | 1.4 MB | 文字行检测 |
| `text_rec_zh13562_fp16_v2.xnet` | 8.4 MB | 文字识别（文件名中的 13562 是字符表大小，中文为主） |
| `paragraph_det_fp16_v2.xnet` | 2.9 MB | 段落检测 |
| `QBarDetV1.7.0.26.xnet` / `QBarSegV1.1.0.26.xnet` | 0.4 / 0.2 MB | 二维码检测与分割 |
| `PrivacyDetectV8.0.26.xnet`、`DeepSR_*.xnet`、`FPMMFG*.xnet` | — | 隐私检测、超分辨率、图片指纹（与 OCR 无关） |

`.xnet` 是腾讯自己的推理格式：`libwxocr` 导出 `OnnxToXNet(...)`（由 ONNX 转换而来），后端有 `xnet::umtl`（Metal）、`xnet::uocl`（OpenCL）、`xnet::ugl4`（OpenGL），并链接 `CoreML`、`MetalPerformanceShaders`、`Accelerate`（BLAS / LAPACK）。

### 3.3 识别流程：检测 → 透视裁剪 → 识别 → 合并段落

`nm` 中 `wevision2` 命名空间的符号按流程排列：

1. `mmfg::OcrApi::init(mmfg::OCRConfig)` / `mmfg::OcrLite::Init`、`setDetResolution(int, int)`：加载模型，设定检测分辨率；
2. `wevision2::TextDetection::Run` → `GetBoxes` / `GetOrientation`：输出文字区域的四边形和方向；
3. `wevision2::ParagraphDetection::UnClip`、`ParagraphDetectionNew::UnClip` 加上 `ClipperLib::ClipperOffset`：把概率图得到的收缩多边形向外扩回去，这是 DBNet 后处理的标志步骤；
4. `wevision2::OCRUtils::WarpPerspective`、`GetPerspectiveWarppedImageSize`：按四边形把每行文字透视矫正成水平小图；
5. `wevision2::TextRecognition::RecognizeTexts` / `RecognizeChars` / `GetChars`、`wevision2::TextRecognitionCPU`：逐行识别；
6. `wevision2::MergeLinesToParagraphs`、`ParagraphRecognizer::Recognize`：把文字行合并成段落，供界面按段落选择和复制。

整体与 PaddleOCR 的“DB 检测 + 识别”两段式结构相同（推断：只能确定结构，模型来源无法从二进制判断）。

## 4. 本项目能否实现

本项目现状：Rust + egui；macOS 用 `CGDisplayCreateImageForRect` 截下整块显示器，在 `NSScreenSaverWindowLevel` 的遮罩里显示这张静止画面（`platform/macos/screen.rs`、`platform/macos/floating.rs`）；Windows 用 BitBlt，遮罩不透明（`ui/snipper/mod.rs` 的 `builder()`）；macOS 最低版本 12.0（`scripts/bundle-macos.sh`）。

结论：两个功能都能做，不需要照搬微信的 OpenCV / 自研推理引擎。

### 4.1 滚动截图

| 环节 | 微信 | 本项目建议 |
| --- | --- | --- |
| 进入方式 | 选区后点“长截图” | 工具栏加一个按钮，选区确定后进入滚动模式 |
| 让滚轮落到下层窗口 | 选区内鼠标穿透 / 转发事件 | 遮罩改为鼠标穿透：egui 0.36 有 `ViewportBuilder::with_mouse_passthrough`，macOS 底层即 `setIgnoresMouseEvents:`（`platform/macos/panel.rs` 已经在用）。只在选区**外侧**画边框，工具栏和预览放到另一个可交互的小视口。Windows 遮罩不透明，滚动模式下要隐藏全屏遮罩，改为只显示边框窗口（`WS_EX_LAYERED \| WS_EX_TRANSPARENT`） |
| 取帧 | ScreenCaptureKit，排除自己的窗口 | 定时（约 80–150 ms）截选区：macOS 继续用 `CGDisplayCreateImageForRect` 截选区矩形，边框画在选区外，不会进入画面；也可用 `CGWindowListCreateImage` + `kCGWindowListOptionOnScreenBelowWindow` 排除遮罩。Windows 继续用 BitBlt。ScreenCaptureKit 要 macOS 12.3+ 且回调是异步的，不是必须 |
| 算偏移 | ORB + BFMatcher（OpenCV） | 不建议引入 `opencv` crate（要求系统装 OpenCV 和 libclang，构建很重）。滚动只是整像素平移，不需要 ORB 应对缩放旋转：纯 Rust 做“行指纹匹配”即可——每行灰度算哈希；去掉两帧中位置不变的顶部 / 底部行（固定标题栏、输入框）；在中间区域找使上一帧底部与新帧顶部重合行数最多的位移，再用像素差验证。偏移为 0 丢弃，找不到重合提示“滚动太快” |
| 拼接 | `SpliceWorker` | 在 `RgbaImage` 画布下方追加新露出的行，设高度上限（例如 30000 像素）防止内存失控 |
| 滚动驱动 | 用户自己滚 | 首版同样由用户滚动；以后可加自动滚动：macOS `CGEventCreateScrollWheelEvent` + `CGEventPost`（需要“辅助功能”权限，自动粘贴已经申请），Windows `SendInput` + `MOUSEEVENTF_WHEEL` |
| 输出 | 预览、编辑、发送 | 长图通常比屏幕高，现有遮罩里的标注编辑（`Capture` 是一块显示器的画面）放不下，宜直接复制 / 保存，或交给贴图窗口（`ui/pin.rs`）缩放查看 |

偏移计算和拼接都是纯函数，可以放进 `snip` 模块，用合成图片写单元测试，与现有选区计算的做法一致。

### 4.2 文字提取

| 方案 | 做法 | 优点 | 代价 |
| --- | --- | --- | --- |
| **A. 系统 OCR（推荐）** | macOS：Vision 的 `VNRecognizeTextRequest`（准确模式，`recognitionLanguages` 设 `zh-Hans`、`en-US`；中文识别从 macOS 11 起支持，项目最低 12.0 满足），用与现有依赖同一套的 `objc2-vision` crate 调用。Windows：WinRT 的 `Windows.Media.Ocr`，需要新增 `windows` crate（特性 `Media_Ocr`、`Graphics_Imaging`、`Storage_Streams`），项目目前只用 `windows-sys` | 安装包不增加体积；结果带每行的位置，可以像微信一样在截图上叠一层可选中的文字 | Windows 识别中文要求系统装有中文 OCR 语言组件（中文版系统默认有，英文版系统需另装）；两个平台识别效果不完全一致 |
| B. 与微信同构 | PaddleOCR 的检测 + 识别 ONNX 模型，用 `ort` crate（ONNX Runtime）推理，自己实现 DB 后处理（UnClip）和 CTC 解码 | 两个平台结果一致，离线可控 | 安装包大约增加 ONNX Runtime 动态库二三十 MB 加模型十来 MB；后处理代码量不小 |
| 不可行 | 直接加载微信的 `libwxocr.dylib` 或 `.xnet` 模型 | — | 私有格式与接口，且有版权和签名问题 |

接入点：截屏工具栏（`ui/snipper/toolbar.rs` 的 `Output`）加“提取文字”，对当前选区（或贴图窗口里的图片）在后台线程识别，结果在面板里显示，可复制，复制的内容进入剪贴板历史。
