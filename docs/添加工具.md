# 添加编译期工具

当前已接入目录发现、通用工具运行时，以及 JSON、时间戳和密码三个共享窗口工具。JSON 核心位于 `json/core/`，密码和时间戳算法位于各自的 `model.rs`，算法与测试均归属工具目录。下面的步骤适用于使用已有宿主能力的新工具。

## 1. 创建目录

在 `crates/devtools-tools/src/tools/` 下新建小写目录，例如 `echo/`，添加 `mod.rs`。不要修改 `lib.rs`、`build.rs`、宿主或中央注册列表。

以下是可以直接使用的完整示例：

```rust
//! 回显工具示例，复制请求由宿主在绘制结束后执行。

use devtools_module_api::{ModuleDescriptor, Selection, ToolEffect, ToolModule};
use devtools_ui::style::Palette;
use egui::{Rect, Ui};
use serde_json::Value;

#[derive(Default)]
struct Echo {
    text: String,
    pinned: bool,
}

impl ToolModule for Echo {
    fn activate(&mut self, input: Option<Selection>) -> Vec<ToolEffect> {
        if let Some(Selection::Text(text)) = input {
            self.text = text;
        }
        Vec::new()
    }

    fn render(&mut self, ui: &mut Ui, _palette: &Palette) -> Vec<ToolEffect> {
        let mut effects = Vec::new();
        ui.heading("回显工具");
        ui.checkbox(&mut self.pinned, "固定窗口");
        ui.text_edit_multiline(&mut self.text);
        if ui.button("复制").clicked() {
            effects.push(ToolEffect::Copy {
                text: self.text.clone(),
                sensitive: false,
            });
            effects.push(ToolEffect::Toast("已复制".into()));
        }
        if ui.button("关闭").clicked()
            || ui.input_mut(|i| i.consume_key(egui::Modifiers::NONE, egui::Key::Escape))
        {
            effects.push(ToolEffect::Close);
        }
        effects
    }

    fn pinned(&self) -> bool {
        self.pinned
    }
}

fn paint_icon(ui: &Ui, rect: Rect, palette: &Palette) {
    ui.painter().circle_filled(rect.center(), rect.width() * 0.4, palette.accent);
}

pub(super) fn descriptor() -> ModuleDescriptor {
    ModuleDescriptor {
        id: "devtools.echo",
        name: "回显工具",
        description: "编辑并复制选中的文本",
        order: 100,
        size: [680.0, 560.0],
        toast_offset: -48.0,
        matches: |input| matches!(input, Selection::Text(_)),
        paint_icon,
        create: |_| Box::<Echo>::default(),
        validate_config: Value::is_object,
        default_hotkey: "",
    }
}
```

工具 ID 是配置与热键身份，发布后保持稳定；目录名可以独立调整。图标在工具内部绘制，无需扩展公共图标枚举。

## 2. 构建与测试

```bash
cargo check -p devtools-tools
cargo test -p devtools-tools
cargo run -p devtools-hub --release
```

构建脚本自动发现所有直属工具目录。缺少入口、非法目录名和符号链接会报错，避免工具被静默遗漏。内部源文件使用普通 `mod model; mod ui;`，内部测试使用 `#[cfg(test)] mod tests;`。

新增工具自动获得托盘、中键及设置页入口。设置页可禁用工具、配置全局快捷键；工具私有设置通过 `settings_ui()` 绘制，`config()` 返回认识的字段，运行时合并保存并保留未知数据。

敏感内容使用 `ToolEffect::Copy { sensitive: true, .. }`，宿主负责附加跨平台隐私标记。不要直接访问系统剪贴板、宿主状态或其他工具内部类型。

## 3. 依赖与格式化

使用现有依赖只增加工具目录。需要新库时更新 `crates/devtools-tools/Cargo.toml` 和必要的 `Cargo.lock`；目录模块没有独立 Cargo 清单。可复用的纯逻辑仍可放在独立领域 crate 中。

生成文件位于 `OUT_DIR`，不提交。IDE 需要启用 Cargo 构建脚本分析。自动生成模块不一定被 `cargo fmt` 遍历到，使用 `cargo run -p devtools-tools --bin tools-fmt` 格式化，或加 `-- --check` 只检查。CI 使用同一 Rust 格式检查入口，自动遍历目录，无需维护逐工具列表。

## 4. 首版范围

当前模块协议支持共享主窗口工具、文本／路径输入、普通／敏感复制、拖动、关闭、提示、独立配置和动态热键。JSON 的文件读取与解析仍沿用同步计算；后台任务统一调度、跨工具动作协议、独立工具窗口和 OCR／搜索适配属于后续阶段，不能当成已经实现的接口使用。
